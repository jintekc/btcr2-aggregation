zustand implements as `getInitialState()`, so `setState` is invisible to `renderStatic`. Seed by prop
or through the selector-faithful fake from `packages/web/tests/support/render.tsx`, and give every
render block an anti-vacuity control.

**Two deliberate departures from the audit's grouped fix plan, stated because the round brief asks
for grouping changes to be justified.**

1. The audit puts #30 and #31 together in `packages/web/tests/cohort-form.spec.ts` and #17 and #23
   with the #1 residual in `packages/web/tests/operator-rows.spec.ts`. That grouping is kept. What
   changes is the METHOD for #31.
2. The audit says #31 "requires a src refactor": extract the edit form's field seeding into
   `packages/web/src/lib/cohort-form.ts` as an exported `formFromDraft`, mirroring the
   `formFromSnapshot` precedent. That proposal existed only because no spec in this repo could
   render a component. The refactor is still not done, but the reason has to be stated precisely,
   because the first version of this plan justified it with a capability claim that turned out to be
   too broad. The harness cannot see store state written with `setState`; what it CAN see is a
   component's props and its `useState` initializers. The seeding under test here is driven by the
   `draft` PROP and evaluated in `useState` initializers, both of which a static render reaches, so
   the render genuinely pins the ACTUAL seeding expression. The form's three incidental store reads
   are handled with the fake if they get in the way. An extracted helper would instead pin a copy of
   the rule and leave the component free to stop calling it, which is the shape of the defect this
   whole round exists to close. So: the render works for this component for a specific and stated
   reason, not because rendering works everywhere.
