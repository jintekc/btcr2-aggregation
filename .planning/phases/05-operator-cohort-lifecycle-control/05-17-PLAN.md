## Gap source

This plan closes **audit defect 3** from `.planning/phases/05-operator-cohort-lifecycle-control/05-AUDIT.md` (entries 1 and 5, HIGH, unauthenticated denial of service), also filed as `.planning/todos/pending/2026-07-29-bound-the-anonymous-terms-acceptance-artifact-store.md`.

It was found INDEPENDENTLY by two agents working different dimensions (`auth-gating` and `coherence`) and confirmed by both skeptics. One skeptic reproduced it in-process: one freshly minted k1 identity, never registered and never seated, posting 300 acceptances naming a nonexistent cohort with `acceptedAt` incremented by one millisecond, produced `{ ok: 300, bad: 0, distinctStored: 300 }`. Sustained throughput measured about 430 accepted writes per second, with the server-side schnorr verify as the practical limiter.

**Read the skeptics, not only the finder.** Three corrections narrow and sharpen the fix:

1. **A default self-host is NOT exposed.** With no terms configured the handler refuses at its first dependency guard, before touching the store. Growth begins only once the operator sets `TERMS_TEXT` or sets terms through the runtime settings surface, which is the intended production posture for SVC-05 but not the out-of-box one. The plan must not overstate the trigger.
2. **The shipped failure mode is heap growth, not disk fill.** `demo-server.ts` constructs a `MemoryArtifactStore` unconditionally; `FileSystemArtifactStore` is only reached by a caller that wires it explicitly. Both are fixed here, but only the memory one ships.
3. **The refusal body must not regress.** The uniform refusal exists so the route is not an enumeration oracle, and the phase's own spec compares six refusal bodies to each other rather than one at a time. The bound must be implemented so that nothing new refuses, which is why this plan evicts rather than caps-and-rejects.

**What the shipped SUMMARY claims, and why it is not enough.** `05-13-SUMMARY.md` and the route's own docstring reason carefully about store growth on the REFUSAL paths (T-05-13-04: an unverified caller cannot grow the store by failing). That argument is sound and stays. The gap is that growth by SUCCEEDING was never bounded, and a caller who mints a k1 DID locally is a verified caller: the signature proves authenticity, not authorization.

**Why a cap-and-refuse design was rejected.** Refusing past a cap trades memory exhaustion for participant lockout: an attacker fills the cap and legitimate joiners can no longer record an acceptance, which breaks the SVC-05 join gate itself. Eviction keeps the route always-accepting and matches the discipline the rest of the service already uses (`MAX_TERMINAL` 24, the operator-actions ring at 100, `MAX_TEST_PEER_DIDS` 200).

Give the one anonymous write path this phase added the same bound every other structure in it already has.

Purpose: `POST /v1/terms/acceptance` is deliberately anonymous, and it should stay that way: requiring a session to accept terms before joining would be circular. What it cannot stay is unbounded. Each accepted record is keyed by the canonical hash of the whole record, so a single differing `acceptedAt` mints a new key rather than overwriting, nothing ever deletes an acceptance, and the store is process-wide on a single-box coordinator whose cohort state is already memory-only.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet -> `POST /v1/terms/acceptance` | The only unauthenticated write path this phase added. A caller can mint valid k1 identities offline, so a verified signature proves authenticity and not authorization. |
| acceptance namespace -> process memory | The store is process-wide on a single coordinator process whose cohort state is already memory-only, so unbounded growth in one namespace takes down every in-flight cohort with it. |
| refusal body -> caller | One uniform body across every refusal path is what keeps the route from being an enumeration oracle for cohorts and DIDs. |
