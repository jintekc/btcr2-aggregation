## The defects, stated precisely

### WR-12: the console's primary action tells an expired operator to try again

Every other gated call in this store discriminates a 401: the four reads, plus discard, export,
cancel, finalize, add-test-peers, pause, resume, disable-broadcast, dismiss and save-draft-edit.
`advertise` (`packages/web/src/stores/operator.ts:1089-1117`) and `readvertise` (`:1119-1139`) do not,
because the API helpers behind them (`packages/web/src/lib/operator.ts:1105-1116` and `:1123-1130`)
collapse every non-ok status into `null` or `false`. So the store's else branch runs and the operator
is told to retry an action that can never succeed, on the primary action of the whole console,
instead of being taken to the login screen with the honest session-expired copy that D-16 makes the
single meaning of a 401.

The same helpers swallow a 409 from the paused-advertising gate (D-06) into the same sentence, where
the service authored a specific reason (`ADVERTISING_PAUSED_REASON` in
`packages/service/src/operator-cohorts.ts`, returned by both routes in
`packages/service/src/hono-adapter.ts`). That 409 is precisely the race the disabled-button reason
exists to prevent: advertising paused between the render and the click.

The list poll corrects the wrong copy within one 4000 ms tick when the operator is on the list view,
which is where these buttons live, so the sentence is transient. What was not transient is that the
message landed in `formError` and `expireSession` did not clear it, so it rendered on the NEXT
session's create form. 05-39 closed that half by making both ending paths clear one list; this plan
closes the half that produced the wrong sentence in the first place.

### IN-09: a rule stated as general law, followed by four call sites of fifteen

`sessionRound`'s docstring says "any guard that must decide whether an answer still belongs to the
session that asked compares this, never `auth` alone". The four gated reads do. The action verbs
(`runAdvertisingToggle:726`, `saveDraftEdit:1078-1080`, and the calls at `:1146`, `:1160`, `:1175`,
`:1199`, `:1224`, `:1257`, `:1277`) call the shared expiry path on a 401 with no capture and no
comparison, and the two advertise verbs did not even reach it. The window is far narrower than a
poll's, which is why the review filed this as info and why the round-6 plan fenced these paths on the
record. What keeps it worth closing is stated in the finding: a rule written down as general law is a
claim about every call site it names, and nine call sites not following it leave the next reader
unable to tell the exemption from an omission.

### IN-10: one rule, two compositions, in one file

`refreshCohorts`'s guard (`:1010`) compares the capture, the auth status AND the round.
`pollDetail` (`:1465`), `loadSettings` (`:1329`) and `saveSettings` (`:1351`) compare the capture and
the round. Before round 6 every probe bumped the round, so all four dropped answers that landed
during a probe window and the asymmetry was invisible. Now a confirming probe leaves the round
intact, so an ok answer landing inside the probe's `checking` window is dropped by the list read
alone and written normally by the other three. The store's own 401 branches already record the
argument for declining a status comparison there ("a status check would additionally refuse a genuine
expiry landing inside a probe's `checking` window and defer it to the next tick for no benefit"), and
that argument applies unchanged to the ok path.

## The rule this plan holds

**One gated verb, one vocabulary. A 401 means the session ended and always takes the operator to one
honest re-login; a refusal the service authored is rendered in the service's words; and whether an
answer still belongs to the session that asked is decided by one comparison, written once, used
everywhere.**

## Which slot the advertise failures land in, and why

`formError` is the create form's validation field: it renders inside `CreateCohortForm`, which is
behind the `New cohort` button, so an advertise failure written there is invisible unless that form
happens to be open. `actionError` is the shipped one-shot action-error field, rendered in bad tone at
the top of `OperatorCohortList` beside the good-tone advertise confirmation and directly above the
rows whose buttons raise it, and it is already the home of a failed discard and a failed dismissal.

So the two verbs move their failure messages to `actionError`, which is what "exactly as
`finalizeCohort` already does" means in this store, and `formError` goes back to being what its own
docstring says it is. The two verb-specific sentences are preserved byte-identically rather than
replaced by the shared action line, because they name the verb and the shared line cannot; the 409
reason is composed with the shipped `actionFailedWith` helper so a refused advertise reads in the
same voice as a refused finalize.
