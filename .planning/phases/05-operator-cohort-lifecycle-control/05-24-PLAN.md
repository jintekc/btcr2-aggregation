**One departure from the audit's grouped plan, stated because the round brief asks for it.** The
audit puts the new fate-read block in `packages/web/src/stores/participant.spec.ts`, the existing
co-located legacy spec. This round puts NEW tests in `tests/` per the standing house rule, so the
block lands in a new `packages/web/tests/participant-fate.spec.ts`. The legacy co-located file is
still edited, but only mechanically, to satisfy the required-parameter change in task 1.

**#13 gets a stronger fix than the audit proposed, and the reason matters.** The audit's closing
test for #13 asserts the fate read's URL and credentials. That pins `fetchCohortFate`, not the poll
closure at `participant.ts:1746` where the argument is actually dropped, and no unit test executes
that closure at all. Making the parameter REQUIRED turns a dropped argument into a compile error,
which is the same reasoning 05-10 used for the cancel fact reaching `terminalReason` ("a forgotten
call site is a compile error rather than a wrong sentence shown to a participant"). That fix only
works because 05-21 put `packages/web` inside `pnpm test`; before this round it would have been
invisible to the gate.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service response to participant narration | A fate answer becomes a public accusation against a named operator, so a fault must never be able to produce one. |
| participant-supplied endpoint to chain reads | An activated endpoint feeds funding reads, confirmations and a direct broadcast, so activating one on the wrong chain risks real funds. |
| expired session to console state | A logged-out operator must not keep seeing a drill-down they can no longer act on. |
