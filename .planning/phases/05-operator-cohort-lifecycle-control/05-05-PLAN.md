## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** participant who lands on a paused service, **I want to** be told plainly that it is not offering new cohorts right now, **so that** I do not mistake a deliberate pause for a dead service.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: `ServiceControls` (packages/web/src/components/operator/ServiceControls.tsx), the `pauseAdvertising` and `resumeAdvertising` clients and store actions, the paused chip on `HealthStrip`, the public paused-notice variants in `BrowseView` and `DirectoryList`, `packages/web/tests/service-controls.spec.ts`, and the e2e leg `e2e:pause`.

<objective>
Give the pause built in 05-04 both of its human faces: an operator control that never over-claims, and a participant notice that never reads as a dead service.

Purpose: a drain-mode pause is only honest if both sides can see it. On the console the operator needs the two reversible controls plus the two pieces of guidance that stop pause from being misunderstood (it does not retract open cohorts, and it does not survive a restart). On the public directory a stranger needs to tell a deliberate pause from an idle service, which is exactly why the paused bit was added to the status read rather than inferred from an empty list.

Output: the `Service controls` card, the health-strip paused chip, disabled advertise controls with their real reason, both public paused-notice variants, predicate coverage, and a hermetic pause e2e leg.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service status read -> anonymous participant UI | The only new fact crossing to strangers is one boolean; nothing about drafts, members, or settings may follow it. |
| operator browser -> gated pause and resume | The console must not be able to claim a service state it did not receive from the server. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05-01 | Spoofing | rendered paused state | medium | mitigate | Both the console state line and the public notice derive only from the served status bit; there is no optimistic set and no inference from an empty directory, so the UI cannot claim a state the service is not in. |
| T-05-05-02 | Information Disclosure | public paused notice | low | accept | The notice exposes exactly one deliberate operator-chosen fact; no draft, member, count, or settings value is added to any anonymous surface. |
| T-05-05-03 | Elevation of Privilege | pause and resume from the browser | high | mitigate | The client calls only the gated routes with `credentials: 'same-origin'`; a 401 routes through the shared expiry path to an honest re-login rather than leaving an authenticated-looking surface. |
| T-05-05-04 | Tampering | operator-supplied service name beside the new chips | high | mitigate | The health strip renders the name as plain auto-escaped React text content, never markup and never a link target, and the new chips are fixed contract copy. |
</threat_model>
