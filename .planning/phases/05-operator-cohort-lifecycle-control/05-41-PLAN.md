## The defects, stated precisely

### IN-13: one fact, three statements, and round 6 corrected one of them

WR-10's premise, which round 6 accepted and acted on, is that a refused boot seed can be repaired in
the running session: `applySettings` accepts a value up to the holder's own character ceiling and
the settings route carries it, so the operator can type into the field the caption sits under, save,
and have the setting back in THIS session. Round 6 corrected exactly one of the three places that
state the repair.

The two boot warnings still end with the environment edit as the only repair
(`packages/service/src/runtime-settings.ts:787` and `:802`: "the display name is left unset until the
value is shortened", "the terms are left unset, so the join flow has no terms step at all until the
value is shortened"), and `docs/DEPLOY.md:510` still says "the name is left unset until you shorten
it" while `:516` says "the join flow has no terms step until you shorten it". Both deploy rows do go
on to say the value is runtime-editable, so the document is incomplete rather than false; the boot
lines are the same overclaim WR-10 named, in the place an operator reads first.

### IN-12: the comment at the consuming end describes the previous derivation

`packages/service/src/hono-adapter.ts:905-914` says the budget "is computed from `MAX_TERMS_CHARS` in
`runtime-settings.ts`". That was true in round 5 and is not true now: 05-38 made the budget carry
`MAX_SERVICE_NAME_CHARS` as well, which is the whole point of IN-06's fix. This is the one comment a
future reader checks first, because it sits on the route that consumes the number.

### IN-14: the budget charges a length the holder has not produced yet

`applySettings` runs its trim first and bounds what is left
(`packages/service/src/runtime-settings.ts:956-959`), so a value with large leading or trailing
whitespace can be legal to the holder and still exceed the route budget, which is enforced during
streaming over the TRANSMITTED body (`hono-adapter.ts:918`). The review measured it with the spec's
own body shape: a 20000 character document padded with 200000 spaces encodes to 420169 bytes against
the 122224 byte limit, so it is refused 413 for a value the holder would have accepted, behind a
sentence naming no field. Not reachable from the console in any realistic use, and unchanged from
every previous budget, so this is a note rather than a defect. It is worth closing because the
module's stated rule is that no value one layer accepts may be refused by another, and an exception
to a stated rule has to be a written decision rather than an accident nobody noticed.

## The rule this plan holds

**A fact stated in more than one place is one fact, and every statement of it has to be corrected
together or they diverge. A comment describing a derivation is a claim about that derivation, and a
documented exception to a module's own rule is a decision that needs a measurement rather than a
rationale.**
