## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator, **I want to** change what my service offers and what it is called from the console, **so that** I stop having to edit environment variables and restart to tune my own service.

This plan also lands the operator half of SVC-05: the participation terms text a participant will be asked to accept in 05-13.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: the wired `applySettings` path for every `RuntimeSettings` field, routes `GET /v1/operator/settings` and `PUT /v1/operator/settings`, the additive `termsText` field on `GET /v1/config`, env seeds `DEFAULT_BEACON_TYPE`, `DEFAULT_SIZE`, `DEFAULT_THRESHOLD`, `DEFAULT_DISCOVERY_WINDOW_MS`, `DEFAULT_FUNDING_WINDOW_MS`, `TERMS_TEXT`, the `TextArea` primitive, `SettingsView` (packages/web/src/components/operator/SettingsView.tsx), the settings console view state, and `packages/web/tests/settings.spec.ts`.

<objective>
Build the env-seeds, runtime-overrides settings surface so the operator can reconfigure this service without restarting it, and so a change is always honestly labelled as a session change rather than a permanent one.

Purpose: SVC-04 criterion 3 has two halves. 05-06 closed the per-cohort half. This is the service half: the defaults every new draft starts from, the service's display name, and the participation terms. The model is deliberate and stated: env seeds the boot value, the console edits the in-memory value, and a restart returns everything to the environment. Nothing persists, because persistence is DUR-01 and adding it here would quietly change the product's state model. Two rules keep this safe: defaults are read once at draft creation so a change can never reshape an existing cohort, and a save applies as a set so the surface can never show a half-saved state.

Output: the wired settings holder, gated settings routes, the additive terms and service-name exposure on the public config read, new env seeds, the `TextArea` primitive, and the third console view.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> gated settings routes | Only an authenticated operator may reconfigure this running service. |
| operator-authored text -> anonymous participant browser | Terms text and the service name are the first long operator-authored strings shown to strangers. |
| environment -> runtime holder -> public config read | Boot seeds flow to a public read; only the two intended fields may cross. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07-01 | Elevation of Privilege | GET and PUT /v1/operator/settings | high | mitigate | Both mount inside the gated block after `requireSameOrigin()` and `requireOperator(...)`; the route-semantics matrix pins the anonymous 401. |
| T-05-07-02 | Tampering | stored cross-site scripting via terms text or service name | high | mitigate | Both render as plain auto-escaped React text content only: no `dangerouslySetInnerHTML`, no link target, no markup rendering, asserted by a repository-wide grep. Both are length-bounded server-side. This is the highest-value new control this plan adds, because terms text is the first long operator-authored string shown to strangers. |
| T-05-07-03 | Denial of Service | unbounded terms text | medium | mitigate | An explicit maximum length is enforced server-side with a user-facing refusal, layered on the 4 KiB body limit, so an operator cannot grow the in-memory holder or the public config response without limit. |
| T-05-07-04 | Information Disclosure | GET /v1/config additive fields | low | accept | Only the operator's chosen public-facing name and terms text cross to anonymous readers; every other holder field stays behind the gated settings read. |
| T-05-07-05 | Tampering | half-applied settings save | medium | mitigate | `applySettings` validates every field before applying any, so a rejected save leaves the service exactly as it was and the console renders the previous served snapshot. |
</threat_model>
