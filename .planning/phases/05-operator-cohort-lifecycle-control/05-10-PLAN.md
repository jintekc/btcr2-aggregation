## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** participant whose cohort was canceled, **I want to** be told that the operator ended it, **so that** I stop waiting on something that will never anchor and know my keys are still mine.

This is the participant-facing half of the cancel slice and the last CORE item of SVC-04. It is deliberately placed before the three folded builds, which are the slip-first tier.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: route `GET /v1/cohort-fate/:id`, `cohortFate` on the operator-cohorts surface, `packages/web/src/lib/cohort-fate.ts` with `fetchCohortFate`, the cancel input on `terminalReason`, and `packages/web/tests/terminal-reason.spec.ts`.

<objective>
Carry the cancel attribution from the service to the participant, and make it impossible for a cancel to be narrated as a stall.

Purpose: the aggregation protocol has no message type that could carry a cancel, so a seated participant learns their cohort is gone only through the directory poll's post-seat gone streak. That streak's two-consecutive-reads requirement exists to win a race against cohort-complete and must not be shortened. What CAN be added is a narrow public fact read, checked once the streak has already triggered, which upgrades the honest fallback into a specific attribution without changing any timing. The dangerous part is the narration path: the shipped `terminalReason` classifier's first branch fires on submitted-but-unsigned plus not-validation-requested plus unexplained, which is exactly what a mid-signing cancel looks like, so it would currently produce the stall copy that 04 D-45 exists to prevent. The fix is a dedicated boolean checked first, never a new alternative in the message-text chain.

Output: a public non-oracle fate read, an anonymous client called once the streak triggers, the cancel input on `terminalReason` checked before the stall branch, both narration variants with their shared next-step line, and a unit spec fed the exact input that currently misfires.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous participant browser -> public fate read | A new anonymous route must not become an existence oracle for this service's cohorts. |
| service fate record -> participant narration | Only one bit crosses; operator-only fields (reason text, member counts, DIDs, amounts) must not follow it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10-01 | Information Disclosure | GET /v1/cohort-fate/:id as an existence oracle | high | mitigate | Unknown, evicted, and never-existed ids all answer a byte-identical 200 body; the route never answers 404 and never varies its shape, and the spec asserts the property by deep-equality rather than case by case. |
| T-05-10-02 | Information Disclosure | fate response contents | medium | mitigate | The projection carries exactly one boolean; the reason string, member list, seat counts, and funding amounts stay behind the gated operator reads. |
| T-05-10-03 | Denial of Service | anonymous fate polling | low | mitigate | The client calls the read ONCE, after the post-seat gone streak has already triggered, rather than adding a new poll loop; the read itself is an O(1) map lookup with no chain or disk I/O. |
| T-05-10-04 | Spoofing | narration attribution | medium | mitigate | The cancel copy renders only when the service itself reports the canceled fact; an unreachable or false read falls back to the honest line rather than guessing, so a network fault can never fabricate an accusation against the operator. |
</threat_model>
