## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator running live, **I want to** stop new cohorts from spending Bitcoin without killing my service, **so that** I can stand down the money-moving leg immediately while everything already in flight finishes as promised.

This plan lands three of the four items earlier phases parked to Phase 5: the broadcast-only kill switch (was 04 D-35), ended-record dismissal (was 04 D-14), and the service-level operator actions log those two need.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: the one-way `broadcastDisabled` flag with its engage timestamp, `dismissEnded` and the service-level `operatorActions` ring (packages/service/src/monitor.ts), `ServiceHealthDTO.broadcastDisabled`, routes `POST /v1/operator/broadcast/disable` and `DELETE /v1/operator/ended/:id`, the `Disable broadcast` control and the `Operator actions` log on `ServiceControls`, the `Broadcast off (this session)` health chip, the ended-row `Dismiss` action, and `packages/service/tests/kill-switch.spec.ts`.

<objective>
Give the operator a runtime brake on money movement, a way to clear finished records off the console, and a service-level record of everything they did this session.

Purpose: ADR 0010's layered environment opt-in is the only path to money movement, and this plan does not weaken it: the switch can only ever move from off to on, no route sets it back, and a restart returns to the boot contract. The subtle part is honesty about in-flight work. The service mode is derived once at construction and cached by the monitor, so the switch must not mutate it; instead the per-cohort broadcast decision compares each cohort's advertise timestamp against the moment the switch engaged, which is what makes "in-flight cohorts finish under the mode they started with" a fact rather than a hope.

Output: the one-way flag and its engage timestamp, per-cohort mode selection at the broadcast handoff, an unmutated boot mode with a separate warn chip, gated disable and dismiss routes, the service-level operator actions log, and the three console surfaces.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> gated disable and dismiss routes | Only an authenticated operator may change money-movement mode or clear telemetry. |
| runtime flag -> money movement | The flag gates whether a real Bitcoin transaction is published; it must only ever move in the safe direction. |
| telemetry store -> protocol state | A dismissal must be provably unable to reach protocol or chain state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08-01 | Elevation of Privilege | POST /v1/operator/broadcast/disable | high | mitigate | Mounted inside the gated block after both prefix guards; the route-semantics matrix pins the anonymous 401. There is deliberately no enable counterpart, so the worst an attacker with a session can do is stand the service DOWN, never up. |
| T-05-08-02 | Tampering | runtime re-enable of money movement | high | mitigate | The holder exposes only a set-true mutator with no reset, and no route sets the flag back; ADR 0010's layered environment opt-in remains the sole path to broadcast. `kill-switch.spec.ts` asserts the absence rather than documenting it. |
| T-05-08-03 | Spoofing | reported service mode after the switch engages | medium | mitigate | The cached boot mode is never mutated or re-derived; the disabled state is a separate bit and a separate chip, so the health strip cannot misreport how the service booted or that its chain reads are still live. |

| T-05-08-06 | Denial of Service | operator actions ring | low | mitigate | Bounded with oldest-first eviction like every other in-memory ring in this service, and served on the existing polled read rather than a new stream. |
