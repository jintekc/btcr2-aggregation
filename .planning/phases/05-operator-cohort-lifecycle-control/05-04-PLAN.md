## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator, **I want to** stop offering new cohorts without killing my service, **so that** I can drain quietly for maintenance while everyone already seated finishes.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: `packages/service/src/runtime-settings.ts` with `SettingField`, `RuntimeSettings`, and `createRuntimeSettings`; `ServiceStatusDTO.paused`; `ServiceHealthDTO.paused`; routes `POST /v1/operator/advertising/pause` and `POST /v1/operator/advertising/resume`; and the specs `packages/service/tests/runtime-settings.spec.ts` and `packages/service/tests/pause.spec.ts`.

<objective>
Introduce the per-service runtime settings holder and use it for the first runtime-controlled behavior: draining advertising.

Purpose: SVC-04 criterion 2 asks the operator to pause advertising without killing the service. Because the boot-time auto-advertise loop was deleted in Phase 1, exactly two functions in this app call `runner.advertiseCohort`, which makes the gate small, provable, and impossible to leak past. The same holder is where the service name, the create-form defaults, the timing windows, the participation terms, and the broadcast kill switch will live, so building it here once is what keeps the later plans additive.

Output: `runtime-settings.ts`, a two-call-site pause gate, gated pause and resume routes, an additive paused bit on the public status read with every committed pin migrated in the same change, the service name served from the holder per request, and two new specs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> gated pause and resume routes | Only an authenticated operator may change whether this service offers new cohorts. |
| runtime holder -> public status read | The paused bit is a deliberate public honesty signal; nothing else from the holder may cross to anonymous readers. |
| environment -> runtime holder | Boot env values seed the holder; malformed values must degrade to defaults rather than poisoning runtime behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-04-01 | Elevation of Privilege | POST /v1/operator/advertising/pause and /resume | high | mitigate | Both mount inside the gated block after `requireSameOrigin()` and `requireOperator(...)`; `pause.spec.ts` pins the anonymous 401. |
| T-05-04-02 | Information Disclosure | GET /v1/status paused bit | low | accept | The paused bit is deliberately public: it is the honesty signal that distinguishes a paused service from an idle one for headless clients. No other holder field is exposed anonymously. |
| T-05-04-03 | Denial of Service | malformed numeric env seed | medium | mitigate | Every numeric seed runs through the NaN-guarded knob helper (the shipped WR-04 lesson), so a malformed value warns and falls back rather than producing a NaN window or interval. |
| T-05-04-04 | Tampering | runtime settings scope | medium | mitigate | The holder is per-`createService` closure state, never a module singleton, so one service in a multi-service process cannot mutate another's configuration. |
