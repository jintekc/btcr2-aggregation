## The defect, stated precisely

### WR-10: the caption points at the slower remedy and implies the faster one does not exist

The third caption reads, in full, for the terms field: `TERMS_TEXT` was set at boot, but this service
refused it as too long, so the join flow has no terms step at all, and this service refuses every
acceptance, until the value is shortened and this service restarts.

The final clause is false, and it is rendered directly beneath the textarea that falsifies it.
`applySettings` accepts a terms document up to the holder's own character ceiling, and since the
derived body budget landed in the same round the route carries it, so the operator can type
participation terms into the field above the caption, save, and have the SVC-05 acceptance gate
enforcing again in this session, with no environment edit and no restart. The same overclaim is in
the display-name cost.

The caption also contradicts the sentence two cards above it on the same screen, which tells the
operator that changes here apply to this running service only and a restart returns every value to
its environment default. One paragraph says a restart is the remedy; the other says a restart is what
UNDOES the remedy. Both are on screen at once.

The consequence is proportionate to what WR-07 was about. The disclosure exists to get the operator
to act, and it points them at the slower of the two actions. For the terms in particular that is time
with the acceptance gate off.

### IN-05: once the operator edits the field, the caption goes back to the claim WR-07 was filed about

The precedence decision reads: a field the operator has already CHANGED this session holds a value
they chose, so the refusal is history about a boot value nothing on screen renders any more, and the
existing changed caption is the honest one.

The premise is false. The changed caption DOES render the boot value: for a refused field it produces
`changed this session (environment default: not set)`. So the moment the operator types terms into a
field whose seed this service refused, the console goes back to making the exact affirmative false
statement WR-07 was filed about, on the same field, in a different sentence. The row at
`packages/web/tests/settings.spec.ts:158-170` currently pins it, asserting the refused variable is
absent from that caption.

It is INFO rather than WARNING because the operator has already acted on that field and the claim is
accidentally right about what a restart yields. What is lost is the reason to go and fix the
environment file, which is the harm the fix's own docstring calls worse than getting a value wrong.

## The rule this plan holds

**A disclosure exists to make someone act, so it has to name the action that is actually available.
Stating a cost and a remedy in one sentence collapses two facts that are true at different times, and
the one the operator can do right now is the one that gets dropped.**

## Two decisions taken on the record

**Precedence is KEPT and the parenthetical is repaired.** The review permits either carrying the
refusal into the changed branch or keeping precedence and correcting the stated rationale. This plan
does both halves of the honest version: the changed caption still wins for a field the operator
edited, because it holds a value they chose and the bad-tone line would keep shouting about a value
nothing renders, AND the environment-default text inside that caption stops reading as an absence.
That keeps the second format's shape intact, so E8 still describes three formats and the amendment is
to what one slot can carry rather than to how many formats exist.

**The cost and the remedy become separate members rather than one longer sentence.** A single string
is what let two facts fuse in the first place, and a test can then only assert on substrings of a
sentence. Splitting them means the pin can assert a property of each: the cost names no restart, the
remedy names both paths.

### What would have caught this and did not

The general lesson, worth carrying past this phase: a sentence that names a REMEDY is a claim about

describes.
