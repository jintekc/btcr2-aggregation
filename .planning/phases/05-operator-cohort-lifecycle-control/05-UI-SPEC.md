# Phase 5: UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **operator control surfaces** on top of the Phase 4 monitoring console (SVC-04): per-cohort `Cancel` and `Finalize now` with a laddered confirmation ceremony, a drain-mode advertising pause with an honest public paused notice, in-place draft editing plus per-draft advanced timing, an env-seeds / runtime-overrides **service settings** surface (create-form defaults, service name, participation terms), the four absorbed parked items (broadcast-only kill switch, ended-record dismissal, service-name edit, badged test peers), and three folded participant-side builds (esplora endpoint override, PSBT registration leg with an import warning, DID-signed terms acceptance at join).

The contract below **EXTENDS** the shipped dark-slate + bitcoin-orange system and the in-house primitives (`packages/web/src/ui/primitives.tsx`). It introduces no new design language and no component library. `01-UI-SPEC.md` is the parent contract and `04-UI-SPEC.md` is the immediate baseline; every token, primitive, tone map, and copy-register rule in those two still holds unless a row below explicitly extends it.

**Copy hard rule (project global CLAUDE.md + MEMORY):** NO em-dash character (the long dash) in ANY string in this spec or in any shipped UI copy derived from it. Use a comma, a colon, parentheses, a period, or a spaced hyphen. Em-dashes in UI-SPEC copy propagate into shipped strings and get checker-BLOCKED.

**Honesty rule carried forward (D-01, D-02, D-05, D-14):** an operator verb exists only where a real library primitive exists. There is no `Close` button (closing is the automatic lock when the nth seat fills, narrated as a lifecycle stage), no un-advertise, and no per-seat kick. A destructive act names its real consequences. Runtime power only ever points in the safe direction.

- `Badge` + `StatusDot` -> the new `Canceled` ended chip, the health-strip `Advertising paused` and `Broadcast off (this session)` chips, the `Test peer` member badge, the `Terms accepted` member badge. Tones fixed under Color.

- `CopyField` / `Mono` -> cohort ids in confirmations, the acceptance-record reference, the PSBT base64 copy chip, the endpoint host.
- `LogPanel` -> the NEW service-level `Operator actions` log (same component, same `LogEntry` shape, server wall-clock `formatTime` prop as in Phase 4) and the existing per-cohort `Activity` ring.

- `OperatorStageTimeline` -> gains the automatic `Closed` (nth seat filled) stage narration and a terminal `Canceled` rendering. It does NOT gain a control; the timeline stays a read surface.

**New primitives permitted this phase (exactly two, added to `ui/primitives.tsx` matching that file's conventions):**

1. `TextArea` - a multi-line sibling of `Input` with identical border/background/focus treatment (`rounded-lg border border-edge bg-canvas px-3 py-2 text-sm`), `min-h-32` (128px), used by the participation-terms setting and the PSBT paste field.
2. `ConfirmPanel` - the laddered confirmation ceremony (D-03). Props: `tone` (`bad` | `warn` | `neutral`), `heading`, `body` (nodes, so disclosure lines stack), optional `typeToConfirm` (the exact string the operator must type, rendering an `Input` plus a live match check that keeps the confirm button disabled until it matches exactly), `confirmLabel`, `cancelLabel`, `onConfirm`, `onCancel`. Renders inline inside the surface it acts on (never a portal, never a modal overlay), so the operator keeps seeing the cohort or setting being changed.

No other new primitives. Everything else composes from the existing set.

**View state (extends Phase 4 D-03):** SPA-internal view state only, NO routed URLs this phase. The operator console at `/operator` now toggles between three views: the cohort list (default), a single cohort drill-down, and the service settings surface. The settings view is reached from a `Service settings` ghost button on the service-controls card and returns via the same `Back to cohorts` ghost link the drill-down uses. Routed URLs remain a later phase.

Phase 5 placements on that grid:

- Service-controls card: a single wrapping row at `px-4 py-2` (16px / 8px), directly under the health strip, chip and button gap `gap-2` (8px), `flex-wrap`.
- Settings surface: one `Card` per group at `p-5` (20px, matching existing section cards), fields at `space-y-4` (16px), the per-field source caption at `mt-1` (4px).
- `ConfirmPanel`: `px-3 py-2` (12px / 8px) matching the shipped inline confirm, internal `space-y-2` (8px), button row `gap-2` (8px).
- Draft-edit form: identical rhythm to `CreateCohortForm` (`space-y-4` inside a `p-5` card); the `Advanced timing` expander inherits the shared `Expander` padding.
- PSBT round trip: two numbered steps as sibling blocks at `space-y-4`; the paste expander inherits `Expander` padding.

Exceptions (inherited from existing primitives, do not "fix", match them):

- Pill/`Badge` padding `px-2.5 py-0.5` (10px / 2px).
- Micro-caption padding `px-3 py-2` on inset chips/banners; small status banners `px-2.5 py-1.5`.
- `Mono` run size and `CopyField` label size are baked into those primitives.
- NEW, on-grid, Phase 5 only: `TextArea` minimum height `min-h-32` (128px); the participation-terms reader container caps at `max-h-64 overflow-auto` (256px); the PSBT paste field caps at `min-h-32` and scrolls.
- Touch target: interactive buttons keep `px-4 py-2` (min height about 36px). The terms-acceptance checkbox and its label form one click target at least 44px tall (`py-2` on the wrapping label plus the 16px control). No icon-only controls are introduced; the file-picker control renders as a styled label at `px-4 py-2`, matching `Button`.

## Typography

**Phase 5 contract (new surfaces): exactly 2 weights and 4 canonical sizes.** Genuinely NEW Phase 5 text is constrained to weights **400 (regular)** and **600 (semibold)** and to the 4 canonical sizes below. Phase 5 introduces no new weight and no new size. The extra weights/sizes named in the carve-out are the frozen Phase 1 shipped system, inherited verbatim; they are NOT Phase 5 introductions and appear ONLY where a Phase 5 surface renders an existing shipped primitive.

Canonical sizes (the only sizes new Phase 5 copy may use):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 12px (`text-xs`, uppercase, `tracking-[0.14em]`) | 600 | 1.4 |
| Heading | 20px (`text-xl`) | 600 | 1.2 |
| Display | 28px (`text-3xl`) | frozen 700 (inherited shipped role; Phase 5 adds no new Display text) | 1.15 |

- **Display (28px):** the shipped `Operator console` landing heading only. The settings view heading uses Heading, not Display.
- **Heading (20px/600):** the settings view title (`Service settings`) and the drill-down cohort title (shipped). Confirmation-panel headings are Body-size at 600, not Heading: a confirm is an inline panel, not a page.
- **Label (12px/600 uppercase):** all `SectionTitle` concern headings, settings field labels (via `Field`), per-setting source captions, log timestamps.
- **Body (14px/400):** all descriptive, consequence, disclosure, help, and status copy, including every confirmation body. Emphasis inside a body run uses 600, never 500 or 700.
- Type-to-confirm input renders its value in `Mono` (inherited size) so a cohort short id is unambiguous; its label and help stay Label/Body.
- Counts inside consequence copy (`{n} seated participants`) render inline in Body at 600 with `tabular-nums`.

### Inherited-system carve-out (frozen Phase 1 shipped system, out of scope for Phase 5 alteration)

Per the project constraint ("established, do not churn without reason") these shipped values are inherited verbatim and are explicitly NOT new introductions. They are permitted ONLY where a Phase 5 surface reuses the exact shipped primitive that carries them:

- **Weight 700 (bold):** shipped Display/Heading roles (`Operator console`, the app wordmark). New Phase 5 text never uses 700.
- **Weight 500 (`font-medium`):** baked into the shipped `Badge` primitive. Frozen inside `Badge` only. New Phase 5 code never writes `font-medium`.
- **Micro-caption sizes 10-11px (`text-[0.6rem]` / `text-[0.65rem]`):** baked into `CopyField`'s label and `LogPanel`'s event-count caption. Frozen inside those primitives. New Phase 5 captions use Label (12px).
- **Mono-run size about 13px (`text-[0.8rem]`):** baked into `Mono`. Frozen. It appears in Phase 5 only by inheritance (cohort ids, endpoint host, PSBT base64, acceptance-record reference).

Net effect: Phase 5 authors exactly 2 weights (400/600) and 4 sizes (12/14/20/28); every other weight or size on screen arrives only through an unmodified shipped primitive.

## Color

Existing `@theme` tokens (OKLCH) in `packages/web/src/index.css`: dark slate canvas, single bitcoin-orange accent, semantic good/warn/bad. Reuse token names (`bg-canvas`, `bg-surface`, `text-accent`, `border-edge`, ...); do NOT hardcode hex.

| Role | Value (token) | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.17 0.015 260)` (`--color-canvas`) | Page/app background, inset field, textarea, terms-reader, and log backgrounds |
| Secondary (30%) | `oklch(0.21 0.018 260)` (`--color-surface`), `oklch(0.26 0.02 260)` (`--color-surface-2`) | Cards, list rows, service-controls card, settings sections, confirm panels, expander bodies |
| Accent (10%) | `oklch(0.74 0.16 55)` (`--color-accent`) | See reserved list below |
| Destructive | `oklch(0.68 0.2 25)` (`--color-bad`) | Destructive confirmations and terminal states only, per the reserved list below |

Text tiers: `--color-ink` (primary), `--color-muted` (secondary/body help), `--color-faint` (captions). Borders: `--color-edge` / `--color-edge-strong`.

**Accent (bitcoin orange) reserved for, explicit list, nothing else:**

- The single primary action button per surface, all inherited, none added this phase: operator `New cohort` and `Advertise cohort` / `Re-advertise`; participant `Join cohort`, the submit CTA, and the registration CTA (which the PSBT wallet path relabels to `Broadcast signed transaction` rather than adding a second accent button).
- The active view indicator (list vs drill-down vs settings; operator vs public wordmark accent).
- Links (underlined, `text-accent`): `View the public directory`, `View on explorer`, explorer links.
- Live/in-progress affordances: `StatusDot` accent tone plus `.pulse` on the ACTIVE lifecycle stage and on the `Filling` / `Co-signing` chips.
- The KEY/EXTERNAL segmented-control selected state (shipped `JoinIdentityStep` treatment), which the PSBT signing-method chooser reuses verbatim.

Accent is NOT applied to: any Phase 5 control (`Cancel cohort`, `Finalize now`, `Pause advertising`, `Resume advertising`, `Disable broadcast`, `Save settings`, `Save changes`, `Edit draft`, `Dismiss`, `Add test peers`, `Download PSBT`, `Use this endpoint`), any confirmation button, the settings source captions, the paused or broadcast-off chips, or any new border.

**Status-chip tone map (extends the fixed Phase 4 map; the eight Phase 4 rows are unchanged):**

| Chip | Tone | Pulse | Meaning |
|------|------|-------|---------|
| `Canceled` | neutral | no | The operator ended this cohort deliberately (D-05). NOT `bad`: nothing went wrong, so it must never read as a failure, and it must never fold into `Failed`. Distinguished from the neutral `Draft` chip by label and by group (`Ended` vs `Drafts`). |
| `Advertising paused` (health strip) | warn | no | New adverts are blocked (D-07). `warn` because it is a deliberate but non-default state a returning operator must notice, not an error. |
| `Broadcast off (this session)` (health strip) | warn | no | The kill switch is engaged for new cohorts (D-14). Rendered beside, never instead of, the served mode chip. |
| `Test peer` (member row badge) | neutral | no | An in-process participant the operator added (D-17). Never accent: a test peer is not a live-progress signal. |
| `Terms accepted` (member row badge, only when terms are set) | neutral | no | An acceptance artifact exists for this member (D-19). Absence means "no acceptance recorded", never "refused". |

**Confirmation ceremony tone ladder (D-03, fixed):**

| Rung | Tone | Actions | Friction |
|------|------|---------|----------|
| 1 | neutral | `Dismiss` an ended record | Simple confirm, no extra input |
| 2 | warn | `Finalize now`, `Fill remaining seats with test peers` | Simple confirm stating the consequence |
| 3 | bad | `Cancel cohort` (unfunded), `Disable broadcast` | Explicit-consequence confirm naming the cohort and its seated-participant count (or, for broadcast, its one-way nature) |
| 4 | bad | `Cancel cohort` on a FUNDED live cohort | Explicit consequence plus the recovery-key state line plus type-to-confirm (`Type {shortId} to confirm.`) |

Every rung uses an action-verb confirm button and states its consequence in text. Tone is never the only carrier: the danger rungs also read `danger` on the button and name the irreversible outcome in words.

**Reversible actions take NO confirmation:** `Pause advertising`, `Resume advertising`, `Save settings`, `Save changes` on a draft, and setting or clearing the esplora endpoint. Adding friction to a reversible act would dilute the ladder.

**Destructive (`--color-bad`) reserved for:** the rung-3 and rung-4 confirmation panels and their confirm buttons, the shipped `Discard draft` button, terminal cohort failure copy and chips, the funding dead-end and window-closed states, the unreachable banner, inline error banners (`border-bad/40 bg-bad/10 text-bad`), and the mainnet REAL FUNDS warning. Never for pause, finalize, dismissal, settings, test peers, cancel-the-form controls, or any navigation.

Semantic `--color-good` stays reserved for confirmed/anchored/funded facts, the connected freshness dot, and transient success lines (`Advertising resumed.`, `Settings updated for this session.`). Semantic `--color-warn` stays reserved for attention states: needs-funding, fallback, paused, broadcast-off, the rung-2 confirms, the PSBT paste warning, the fit warning, and observation-gap uncertainty.

## Copywriting Contract

Clean operator/service/aggregator framing. NO "booth" / "attendee" / "demo" / "filler" wording in any new string (HOST-03 posture; test peers are framed as rehearsal, never as demo filler). Sentence case for buttons and copy; the operator is addressed directly ("you" / "your service"). Plain-first, raw protocol detail behind the technical expander. Every claim is mode-honest and every disabled control states its real reason.
