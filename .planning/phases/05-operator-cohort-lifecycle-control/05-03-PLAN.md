## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator, **I want to** finalize a cohort whose signing round has stalled, **so that** it anchors on the k-of-n fallback path instead of dying, and I never see a button that only throws.

This plan closes the finalize half of the ROADMAP's open, close, finalize sentence, and lands the honest answer to close: there is no close button, because there is no close primitive. Closing is the automatic lock at the nth seat, narrated as a stage.

<objective>
Wrap `runner.triggerFallback` in an honest operator verb, and narrate the automatic close as a stage rather than faking a control for it.

Purpose: `triggerFallback` calls `session.startFallbackSigning` FIRST, which throws when the cohort is unknown or has no signing session, and only then commits the fallback path and emits. So availability is a phase predicate, not a try/catch. The library's own stall timer keys on exactly three signing phases, and this app's existing `IN_FLIGHT_PHASES` is deliberately wider (it gained the four funding-wait phases in 04-08), so reusing it here would offer a button that throws. Mirroring the library's set into `packages/shared/src/phases.ts` gives the client predicate and the server guard one shared truth.

Output: `FINALIZABLE_PHASES`, a pre-guarded `finalizeCohort`, a gated route that answers 409 with human copy instead of 500, the `Finalize now` control with its rung-2 ceremony, the automatic `Closed` and terminal `Canceled` stage narration, the honest seat-reclaim workaround note, and an operator-triggered fallback e2e leg.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> gated finalize route | An unauthenticated client must not force another operator's cohort onto the fallback signing path. |
| library error surface -> HTTP response body | A raw `AggregationServiceError` message must never become an HTTP body or a rendered string. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-03-01 | Elevation of Privilege | POST /v1/operator/cohorts/:id/finalize | high | mitigate | Registered inside the gated block after `requireSameOrigin()` and `requireOperator(...)`; `lifecycle-routes.spec.ts` pins the anonymous 401 before any lookup. |
| T-05-03-02 | Information Disclosure | 409 refusal body | medium | mitigate | The refusal body is a fixed app-authored message, never the library's thrown text, so internal phase names and cohort internals are not disclosed to a caller. |
| T-05-03-03 | Denial of Service | repeated finalize calls | low | mitigate | `triggerFallback` is idempotent and the pre-guard rejects non-signing phases without touching the library; the activity ring is bounded and de-duplicates identical consecutive entries. |
| T-05-03-04 | Repudiation | operator action attribution | low | mitigate | Every successful finalize appends a server wall-clock-stamped activity entry through `noteOperatorAction`; no cryptographic non-repudiation is claimed. |
</threat_model>
