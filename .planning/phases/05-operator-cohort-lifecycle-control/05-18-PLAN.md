## Gap source

This plan closes **audit defects 5 and 6** from `.planning/phases/05-operator-cohort-lifecycle-control/05-AUDIT.md` (entries 7 and 8, both HIGH), filed as `.planning/todos/pending/2026-07-29-apply-the-discovery-window-ceiling-to-the-env-seed-path.md` and `.planning/todos/pending/2026-07-29-remove-the-dead-fillers-cohort-model-from-the-deploy-docs.md`.

The two are planned together because they are one job: make the knobs the code reads and the knobs the docs promise agree. The seed clamp changes what the code does; the second task then states the resulting rule correctly in all three places that currently promise something else.

**Read the skeptics, not only the finder.** Two corrections change the fix and one narrows the framing:

1. **The over-long app timer does not exist.** The finder claimed `advertiseDraft` arms a 60-minute app timer. Both skeptics showed `armWindowTimer` returns early when the window is at or above `cohortTtlMs`, so NO app timer is armed at all: the cohort lapses on the library's own TTL and settles with the generic expired fate instead of the app's window-expired reason, while the operator DTO and the create form still advertise the longer window. Same bad outcome, different mechanism, so the spec must target the real one. Do not write a test that asserts a timer count.
2. **The save block is not literally silent.** The console's settings form always resends the discovery field prefilled from the snapshot, so the operator sees the offending field and can recover by lowering it in the same save. The accurate statement is that NO settings save succeeds until the operator lowers a discovery default they never chose, and the refusal names a limit the service seeded past itself. The silent part is the boot (no warning, no clamp) and the gated read, which captions an unenforceable value as the env default.
3. **`MIN_PARTICIPANTS` is not dead**, it is mis-described. It is still read and still seeds the new-draft default size through `defaultSize`, and on the documented compose path it is fully shadowed because the compose file always sets `DEFAULT_SIZE`. So its table row needs correcting, not deleting. The hard defect is the retired filler knob plus the quick-start narrative built on it.
4. **The runbook is not a dead end**, it misdirects. The operator password is in the env table and the operator console and its test-peer control are described later in the same file, so a reader who continues gets two mutually inconsistent stories, and a reader who stops after the quick start is stranded.

**Design decision this plan locks, because the todo left it open.** The todo says to choose deliberately between clamping with a loud warning and refusing to boot with the real maximum named, and to make the docs and the code agree either way. This plan chooses **clamp with a loud warning**, for four reasons: it matches the established posture for every other seed in this file; refusing to boot turns one typo in a stranger's env file into a crash loop on the very path the project's core value depends on; clamping makes the console's env-default caption honest, because the value shown is then the value in force; and it closes the settings-bricking consequence by construction, since no over-ceiling value can be stored for a later save to re-read. The docs then state the two rules distinctly: a boot seed is clamped with a warning, a runtime save is refused with the maximum named.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| boot environment -> in-memory settings holder | Operator-supplied numbers seed values every future draft inherits; a value the service cannot honor is a promise it will break. |
| settings holder -> the settings save path | A stored value is re-read for every absent key on save, so one bad stored value can refuse changes to unrelated fields. |
| published runbook -> a self-hosting stranger | The runbook is the only instruction set a stranger has. A knob it documents that no code reads is a defect in the product, not only in the prose. |
