## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator, **I want to** cancel a cohort I no longer want to run, **so that** it stops being joinable immediately and my console tells the truth about why it ended.

This plan is the phase TRACER. It proves the load-bearing architectural pattern the whole phase rests on (RESEARCH Pattern 1: declare intent, then stop) end to end through every server layer, and repairs the transport advert-slot defect that cancel would otherwise turn from a latent bug into a button (RESEARCH Pitfall 3). Every later lifecycle verb rides this seam.

<objective>
Build the cancel vertical slice end to end through every server layer, and repair the transport advert slot it invalidates.

Purpose: `runner.stopCohort` is SILENT (it emits no runner event at all, only flipping `ctx.settled`, disposing the cohort, removing it from the session and rejecting its completion). Every fate consumer in this app learns cohort outcomes from `runner.on(...)` handlers or from the completion rejection, so a naive `stopCohort` call would produce NO monitoring record and would file the cancel as `state: 'expired'` with the machine string `Cohort {id} stopped.`. The fix is not "call and observe" but "declare the intent, then call", and that intent registry is also what makes the per-draft discovery window (plan 05-06) possible.

Output: `cohort-intent.ts`, `advert-republish.ts`, a `cancelCohort` action with a distinct `canceled` fate propagated to all three mirrored server sites, a gated cancel route, funding-watch retirement on cancel, advert-slot repair on every settle path, a new unit spec, and a hermetic two-cohort e2e leg.
</objective>
