## Phase Goal

Sourced from ROADMAP.md Phase 5:

> The operator runs aggregation and manages a cohort's lifecycle (open -> close -> finalize) and pauses, cancels, or reconfigures advertising from the console, without restarting the process, removing the last hardwired, uncontrollable behavior.

MVP slice framing: **As a** self-hosting service operator, **I want to** change a cohort's shape and timing before I advertise it, **so that** I can tune what my service offers without editing env vars or restarting.

## Artifacts this phase produces (Phase 5, cumulative - excludes these from drift verification)

See the cumulative list in `05-01-PLAN.md`. This plan creates: `updateDraft` (packages/service/src/operator-cohorts.ts), the per-draft `discoveryWindowMs` and `fundingWindowMs` draft fields, the app-side discovery-window timer using the `window-expired` intent, route `PATCH /v1/operator/cohorts/:id`, `DraftEditForm` (packages/web/src/components/operator/DraftEditForm.tsx), the shared `Advanced timing` expander, and the specs `packages/service/tests/draft-edit.spec.ts` and `packages/service/tests/discovery-window.spec.ts`.

<objective>
Close SVC-04 criterion 3's per-cohort half: edit a draft in place, and give each draft its own discovery and funding windows within the limits the library actually permits.

Purpose: today the only way to change a draft is discard and recreate, and every timing knob is a boot env var. The honest ceiling matters here: `cohortTtlMs`, `phaseTimeoutMs`, and `advertRepeatIntervalMs` are all PER-RUNNER constructor options and `advertTtlMs` is per-transport, so no timing value in `aggregation@0.4.0` is per-cohort. A per-draft discovery window is therefore enforced app-side by the same intent-tagged `stopCohort` the tracer built, and can only ever shorten a cohort's life. The funding window is different: it is app-owned already, so a genuine per-cohort value works there provided the 04 clamp still computes the same minimum and still throws its specific reason before either library timer.

Output: `updateDraft` with create-identical validation, per-draft windows with a shorten-only ceiling refused honestly at save, an intent-tagged window timer, a gated PATCH route, the `DraftEditForm` with its `Advanced timing` expander, and two new specs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> gated PATCH route | Only an authenticated operator may reshape a draft on this service. |
| operator input -> cohort config | Draft input crosses into a `buildCohortConfig` call and, once advertised, into a public advert; it must be validated before the library sees it. |
| app timer -> runner protocol state | An app-side timer can end a cohort, so it must be bounded, cancellable, and unable to fire against a reused id. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06-01 | Elevation of Privilege | PATCH /v1/operator/cohorts/:id | high | mitigate | Mounted inside the gated block after both prefix guards; `draft-edit.spec.ts` pins the anonymous 401 before any lookup. |
| T-05-06-02 | Tampering | draft input reaching buildCohortConfig | high | mitigate | `updateDraft` reuses the single `validateDraft` guard chain, so a raw library throw can never become the response body and no rule is enforced on create but skipped on edit. |
| T-05-06-03 | Denial of Service | PATCH body size | medium | mitigate | The route carries the established 4 KiB `bodyLimit` with a 413 handler, matching the create POST. |
| T-05-06-04 | Denial of Service | per-cohort discovery-window timers | medium | mitigate | One timer per advertised cohort, held in a bounded per-cohort map, `unref`'d, aborted on the stop controller, and cleared on every settle path, so an operator advertising many cohorts cannot accumulate timers. |
| T-05-06-05 | Tampering | a timer firing against a reused cohort id | medium | mitigate | The timer is cleared on every settle path before an id could be reused, and the intent registry is cleared at settle, so a late fire cannot mislabel a different cohort's fate. |
