## Phase Goal

See ROADMAP.md Phase 4. This plan retires the read-only booth-era telemetry channel (dashboard SSE + Dashboard tab) and replaces it with ONE polled data path (D-19), then merges monitoring state into the operator cohort-list summary read so the console's list surface (chips, metrics) is powered by the new read model.

<objective>
Land the two cross-cutting changes that the whole phase depends on, atomically:
1. Retire dashboard-sse.ts + /dashboard/events + the client Dashboard tab (D-02/D-19), lifting the serialize()/summarizeTx payload helpers into monitor.ts before deletion, and migrating every committed consumer/test pin in the SAME change (Pitfall 1, planning note 1) so the CI gate never goes red mid-change.
2. Grow the monitor into a `summary()` read (per-cohort status-chip key + service-level counts, ended taxonomy folded from completion rejections + broadcaster frames) and merge it into `GET /v1/operator/cohorts` (D-06/D-20/D-23), keeping public DTOs byte-frozen (D-26).

Purpose: collapse two telemetry paths into one polled snapshot and give the console list surface (built in 04-03) its data. Reversibility: retiring the SSE channel is a costly decision (supersedes ADR 0004; the new ADR is authored in 04-08) - flagged, not gated.
Output: dashboard-sse.ts deleted, all pins migrated green, monitor.summary() serving chips + metrics, public DTOs unchanged.
</objective>
