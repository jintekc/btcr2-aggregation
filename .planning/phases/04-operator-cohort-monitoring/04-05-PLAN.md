## Phase Goal

See ROADMAP.md Phase 4 + the phase's co-equal live-path core (D-55): "the actual real server working out-of-the-box, not via an e2e script." This plan makes a real boot able to enable live co-sign + broadcast behind ADR 0010 guard rails (D-35), hardens the one-shot broadcast send into a bounded retry (D-41), and surfaces the resolved live mode + esplora reachability into the health strip (D-17/D-43). The funding stage itself is 04-06.

Requirement LIVE-01 (formalized this phase per planning note 4): the live broadcast path is operable from the product itself, behind guard rails, with honest failure copy.

<objective>
Wire the live-path boot enablement that `demo-server.ts` never did (RESEARCH confirms it never passes live/broadcast into createService): a new `BROADCAST=1` env (requires `LIVE=1`) passes `{ live: true, broadcast: true }`, `LIVE_CHANGE_ADDRESS` and a `FUNDING_WINDOW_MS` knob join the passthrough, with a loud boot banner + RECOVERY_KEY-absent warn + a fail-fast PHASE_TIMEOUT_MS > funding-window invariant (the phase-timeout leg of D-38). Harden `broadcast.ts` into a bounded backoff send retry (D-41). Surface the resolved mode + esplora reachability into the monitor summary so the health strip reads honestly (D-17/D-43).

Purpose: a stranger can boot a real live aggregator behind guard rails; a transient send hiccup no longer loses a cohort's anchor.
Output: BROADCAST env contract + boot invariants + bounded send retry + honest mode/esplora signal.
</objective>

| Boundary | Description |
