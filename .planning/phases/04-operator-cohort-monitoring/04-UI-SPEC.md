# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase reworks the authenticated operator console from a two-step create form plus a read-only telemetry tab into a **list-first monitoring surface with per-cohort drill-down** (SVC-03), and adds the **live-path operability surfaces** (funding stage, live/broadcast mode disclosure, honest anchor and stall copy). The booth-era Dashboard tab, `DashboardView`, `CohortCard`, `MetricsStrip`, and the client-side SSE store retire (D-02). The contract below EXTENDS the established dark-slate + bitcoin-orange system and the in-house primitives (`packages/web/src/ui/primitives.tsx`); it does NOT introduce a new design language or a component library. The Phase 1 contract (`01-UI-SPEC.md`) is the parent; every token, primitive, and copy-register rule there still holds.

**Copy hard rule (project global CLAUDE.md + MEMORY):** NO em-dash character (the long dash) in ANY string in this spec or in any shipped UI copy derived from it. Use a comma, a colon, parentheses, a period, or a spaced hyphen. Em-dashes in UI-SPEC copy propagate into shipped strings and get checker-BLOCKED.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | in-house primitives (`packages/web/src/ui/primitives.tsx`: `Card`, `Button`, `Badge`, `StatusDot`, `SectionTitle`, `Mono`, `CopyField`, `Input`, `Select`, `Field`) over Tailwind CSS v4 |
| Icon library | none. No icon font or SVG set. Status is conveyed by `StatusDot` (colored dot plus optional live pulse) and `Badge` pills. Do NOT introduce an icon dependency this phase. |
| Font | Body/UI: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`. Mono: `--font-mono` (`ui-monospace, "SF Mono", "JetBrains Mono", "Fira Code", monospace`) for DIDs, hashes, cohort IDs, pubkeys, txids, beacon addresses. |

**shadcn gate outcome:** intentionally NOT initialized (identical to Phase 1). A mature custom design system already exists (Tailwind v4 `@theme` tokens in `packages/web/src/index.css` plus typed primitives). The gate precondition "no design system detected" is false, and the project constraint (CLAUDE.md: stack is "established, do not churn without reason") makes adding shadcn a churn with zero requirement coverage. Extend the existing primitives instead. Registry safety gate: not applicable.

**Reuse map (existing -> Phase 4 use):**
- `Card` -> health strip container, metrics row, each cohort list row/group, drill-down concern sections (members, submissions, anchor detail, funding stage, activity log), export card.
- `Button` variants `primary` / `ghost` / `danger` -> `New cohort` and `Advertise cohort` (primary, the only accent buttons), back link and `Download monitoring record` and `Sign out` (ghost), inherited `Discard draft` (danger). No new destructive action ships this phase.
- `Badge` + `StatusDot` tones (`neutral`/`accent`/`good`/`warn`/`bad`) -> live status chips on list rows and the per-member round-state indicators. Tone assignments are fixed below (Color).
- `SectionTitle` -> drill-down concern-section headings and health-strip / metrics labels (uppercase micro-label style).
- `CopyField` / `Mono` -> cohort IDs, member DIDs (shortened display plus copy-full), pubkeys (behind the expander), beacon funding address, txids.
- `LogPanel` -> the per-cohort activity log inside the drill-down. REUSE the component, but the timestamp column renders the server wall-clock stamp (D-22), not the participant-side elapsed `fmtElapsed`. The `LogEntry` shape (`id`, `t`, `level`, `text`) is preserved; `t` carries the server-stamped wall-clock time.
- The participant `StageTimeline` pattern (`components/cohort/StageTimeline.tsx`) -> the operator drill-down cohort-lifecycle timeline at the top of the page (D-05). Mirror the visual treatment (completed = good dot, active = pulsing accent dot, pending = dim neutral); operator stages run advertise -> filling -> submissions -> co-signing -> funding (live only) -> anchor. Do NOT import the participant component directly; the operator timeline has a different stage set. Extract shared visual scaffolding only if it stays honest for both.
- The `Expander` pattern (collapsed-by-default, scrolls overflow, from `components/cohort/CompletionSummary.tsx`) -> the per-row "technical" detail (pubkeys, raw signed-update JSON) and the anchor raw detail. Lift `Expander` into `ui/primitives.tsx` (it is currently local to `CompletionSummary`) so both the participant and operator surfaces share one implementation; matches D-12 plain-first + technical-expander register.

**New primitives permitted this phase (add to `ui/primitives.tsx`, matching the file's conventions):**
- Promote the local `Expander` to a shared primitive (see above).
- A compact `HealthStrip` chip row is composed from existing `Badge` / `StatusDot` / `Mono`, not a new primitive.
- No other new primitives. Everything else composes from the existing set.

**View state (D-03):** SPA-internal view state only, NO routed URLs this phase. The operator console at `/operator` toggles between the cohort list (default) and a single active drill-down via component state, mirroring the participant `participantView` toggle in `App.tsx`. The back link returns to the list. Routed URLs for both sides land in a later phase.

## Spacing Scale

Declared values (Tailwind v4 defaults, all multiples of 4), inherited from Phase 1:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, dot-to-text (`gap-1`) |
| sm | 8px | Compact element spacing, badge/dot gaps, chip rows (`gap-2`) |
| md | 16px | Default element spacing, list-row card padding (`p-4`), section rhythm (`space-y-4`) |
| lg | 24px | Concern-section padding (`p-5` = 20px for section cards), console block margins (`space-y-6`) |
| xl | 32px | Layout gaps between major console blocks |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

- List-row card padding: `p-4` (16px). Drill-down concern-section cards: `p-5` (20px), matching existing section cards.
- Health strip: a single-line `Card` at `px-4 py-2.5` (16px / 10px), chip gap `gap-2` (8px), wraps on narrow widths (`flex-wrap`).
- Activity log container height mirrors the retired dashboard `LogPanel` usage (`h-[28rem]` or a drill-down-appropriate fixed height with internal scroll); never grows the page.

Exceptions (inherited from existing primitives, do not "fix", match them):
- Pill/`Badge` padding `px-2.5 py-0.5` (10px / 2px).
- Micro-caption padding `px-3 py-2` on inset chips/banners; small status banners `px-2.5 py-1.5`.
- Touch target: interactive buttons keep `px-4 py-2` (min height about 36px). Any icon-only control must be at least 44px square. None are planned; status is dots and pills, not icon buttons.

## Typography

Canonical roles (4 sizes, weights 400 + 600, with the documented 700 exception), inherited from Phase 1:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 12px (`text-xs`, uppercase, `tracking-[0.14em]`) | 600 | 1.4 |
| Heading | 20px (`text-xl`) | 700 | 1.2 |
| Display | 28px (`text-3xl`) | 700 | 1.15 |

- **Display (28px/700):** the operator console landing heading only (`Operator console`). The drill-down page heading uses Heading, not Display.
- **Heading (20px/700):** the drill-down cohort title (`Cohort {shortId}`) and the app wordmark.
- **Label (12px/600 uppercase):** `SectionTitle` concern headings (Members, Submissions, Anchor, Funding, Activity), health-strip labels, metrics captions.
- **Body (14px/400):** all descriptive/help/status copy, member rows, submission rows.
- **Bold (700)** remains the documented exception, reserved for Display/Heading and the metrics stat counters (`tabular-nums`). Never for body or label runs. Do not introduce `font-medium` (500) in new code; use 600 for emphasis. (Note: the inherited `Badge` primitive uses `font-medium`; that is pre-existing and stays, do not churn it.)

Micro-caption exception: 10-11px uppercase captions (`text-[0.6rem]`/`text-[0.65rem]`, e.g. `CopyField` labels, log event-count, "Updated Ns ago") are inherited and permitted for dense secondary metadata only. Mono runs render at about 13px (`text-[0.8rem]`). Activity-log lines render at `text-xs` mono (matches `LogPanel`).

## Color

Existing `@theme` tokens (OKLCH) in `packages/web/src/index.css`: dark slate canvas, single bitcoin-orange accent, semantic good/warn/bad. Reuse token names (`bg-canvas`, `bg-surface`, `text-accent`, `border-edge`, ...); do NOT hardcode hex.

| Role | Value (token) | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.17 0.015 260)` (`--color-canvas`) | Page/app background, inset field and log backgrounds |
| Secondary (30%) | `oklch(0.21 0.018 260)` (`--color-surface`), `oklch(0.26 0.02 260)` (`--color-surface-2`) | Cards, list rows, concern sections, health strip, expander bodies |
| Accent (10%) | `oklch(0.74 0.16 55)` (`--color-accent`) | See reserved list below |
| Destructive | `oklch(0.68 0.2 25)` (`--color-bad`) | Terminal failure, dead-end funding, unreachable banner, inline errors, inherited discard/mainnet warnings only |

Text tiers: `--color-ink` (primary), `--color-muted` (secondary/body help), `--color-faint` (captions). Borders: `--color-edge` / `--color-edge-strong`.

**Accent (bitcoin orange) reserved for, explicit list, nothing else:**
- The primary action buttons only: `New cohort` and `Advertise cohort` (`bg-accent text-accent-ink`).
- The active view indicator (list vs drill-down / operator vs public wordmark accent).
- Links (underlined, `text-accent`): explorer links, the quiet view-as-participant link, `View on explorer`.
- Live/in-progress affordances: `StatusDot` accent tone plus `.pulse` ring on the ACTIVE cohort-lifecycle stage in the timeline, and on the `Filling` and `Co-signing` list-row chips (a cohort mid-flight reads live). The freshness "connected" dot in the health strip is `good` tone, not accent (it is a health signal, not a live-progress signal).

Accent is NOT applied to: every button, every border, non-primary focus rings, the metrics counters, the health-strip mode chip, or any attention chip that is not genuinely a live-progress state. Attention that needs a human (needs funding, fallback) uses `warn`, not accent.

**Status-chip tone map (D-04 live status chips, fixed):**

| Chip | Tone | Pulse | Meaning |
|------|------|-------|---------|
| `Draft` | neutral | no | Configured, not advertised (inline row, D-09) |
| `Filling` | accent | yes | Advertised, seats filling (live) |
| `Co-signing` | accent | yes | Signing round in flight (live) |
| `Needs funding` | warn | no | Live cohort awaiting operator funding (attention) |
| `Fallback` | warn | no | Anchored via k-of-n script-path fallback (D-33) |
| `Anchored` | good | no | Beacon tx confirmed (reserved for confirmed only, D-18) |
| `Failed` | bad | no | Cohort failed (terminal) |
| `Expired` | bad | no | Discovery window lapsed (inherited, D-10) |

**Funding-stage state tones (D-36, fixed):**

| State | Tone | Meaning |
|-------|------|---------|
| Waiting for funds | warn | No spendable UTXO selected yet (attention) |
| Funding seen, awaiting confirmation | accent | A candidate UTXO is in the mempool, not yet confirmed |
| Funded | good | The selected confirmed UTXO meets the minimum |
| Funded below the minimum (dead-end) | bad | Terminal: the selected confirmed UTXO is under the minimum band and topping up cannot fix it |
| Funding window closed | bad | Terminal: the window lapsed before funds arrived |
| Could not observe the chain | warn | Uncertainty-honest: observation gaps spanned the lapse (D-39) or esplora unreachable mid-flight (D-43) |

**Anchor detail (D-18, mirrors participant D-22):** Signed -> Broadcast (txid plus explorer link) -> Confirmed; freeze at first confirmation; "Anchored" narration reserved for `state === 'confirmed'` only. Broadcast reached uses neutral-to-good progression; a failed broadcast marks the reached-but-unconfirmed step `bad`. Reuse the `AnchorSubSteps` visual pattern from the participant timeline.

**Destructive (`--color-bad`) reserved for:** terminal cohort failure copy and chips, the funding dead-end and window-closed states, the "Can't reach this service" unreachable banner, inline error banners (`border-bad/40 bg-bad/10 text-bad`), the inherited `Discard draft` button and mainnet REAL FUNDS warning. Never for advertise, back navigation, export, or ordinary monitoring surfaces.

Semantic `--color-good` (success) and `--color-warn` (attention) are for status only: good for confirmed/anchored/funded and the connected freshness dot; warn for needs-funding, fallback, truncated-window disclosure, and observation-gap uncertainty.

## Copywriting Contract

Clean operator/service/aggregator framing. NO "booth" / "attendee" / "demo" wording in any new string. Sentence case for buttons and copy; the operator is addressed directly ("you" / "your service"). Plain-first, raw protocol detail behind the technical expander (D-12). Every claim is mode-honest: a positive terminal claim ("Anchored", "Funded", "funding never arrived") is made ONLY from an observed fact (D-18/D-38/D-39); unknowable progress is stated as unknown, never invented (D-32).

| Element | Copy |
|---------|------|
| Primary CTA | `New cohort` |
| Empty state heading | `No cohorts yet` |
| Empty state body | `Create a cohort to advertise it into this service's directory. This service keeps cohort state in memory, so a restart clears it.` |
| Error state | `Can't reach this service. Showing the last known state and retrying quietly.` |
| Destructive confirmation | Discard draft (inherited, unchanged): `Discard this draft? It hasn't been advertised, so nothing has been published to the directory yet.` confirm `Discard draft`, cancel `Keep draft`. No new destructive action ships this phase. |

Full string set for this phase (all em-dash-free):

**Console shell / list-first (D-07, D-08, D-13)**
- Landing heading (Display): `Operator console`
- New-cohort button (primary): `New cohort` (reveals the create form; the form is hidden by default)
- Create-form dismiss (ghost): `Cancel`
- After advertising a draft, land in that cohort's drill-down (D-13); the transient good-tone confirm stays: `Advertised. Now joinable in the directory.`
- List group headings (SectionTitle): `Needs attention`, `Active`, `Drafts`, `Ended`
- View-as-participant link (quiet accent link, opens `/` in a new tab, D-15): `View the public directory`

**Health strip (D-17, always visible, compact)**
- Mode chip: `Live` (broadcast on), `Live (no broadcast)` (live esplora, fixture co-sign), or `Hermetic` (fixture path). Read-only; runtime toggling is Phase 5.
- Network chip: `{activeNetwork}` (reuse the existing network badge; keep the mainnet `· REAL FUNDS` bad-tone variant).
- Esplora chip (live only): `Esplora reachable` (good) / `Esplora unreachable` (warn, D-43).
- IPFS chip: `IPFS on` / `IPFS off`.
- Service name (D-51): `{SERVICE_NAME}` shown plainly beside the mode chip when set; omitted when unset.
- Freshness indicator (D-25): a `good` connected dot plus `Updated {n}s ago`; on stale reads the dot goes `warn` and the label freezes honestly.

**Service-level metrics row (D-06, compact live counts, no cumulative counters)**
- `{n} open` / `{n} in flight` / `{n} anchored` / `{n} failed` (tabular-nums counters, `SectionTitle`-style captions). Derived from the live set plus retained records; never a since-boot total.

**Drill-down (D-01, D-05, D-11)**
- Back link (ghost, with cross-cohort attention badge when another cohort needs attention, D-11): `Back to cohorts` plus a warn-tone count badge `{n} need attention`.
- Cohort title (Heading): `Cohort {shortId}` with a `CopyField` for the full id.
- Stage-timeline section: no heading text needed; the timeline is the visual anchor (mirrors participant `StageTimeline`).

**Members (D-28, D-29, D-31)**
- Section title: `Members`
- Empty (advertised, none joined): `No one has joined yet. Seats: {joined}/{capacity}.`
- Seated member row: full DID via shortened display plus copy-full (`Mono` + `CopyField`), onboarding model badge when known (`KEY` / `EXTERNAL`).
- Pending opt-in (distinct from seated, D-29): a `Pending` neutral badge and the line `Joining, not yet seated.`
- Per-member round-state chips (D-31, one place answers "who is holding this cohort up"): `Seated` (neutral) / `Submitted` (accent) / `Validated` (accent) / `Nonce sent` (accent) / `Rejected` (bad). Rejections also appear in the activity log.
- Pubkeys (participantPk / communicationPk) live behind the row's technical expander only (D-28): expander title `Technical detail`.

**Submissions (D-30)**
- Section title: `Submissions`
- Who submitted / who has not, with wall-clock timestamps: `{shortDid} submitted at {time}` / `{shortDid}: not yet submitted`.
- Raw signed-update JSON behind the expander: expander title `Raw signed update`.

**Co-sign progress (D-32, honest partial-sig limit)**
- Per-participant where events carry identity (nonce received, validation received): `{k} of {n} nonces received`, with per-member `Nonce sent` chips.
- Partial-signature leg (NO library event, D-32): the honest line `All {n} nonces received. Awaiting partial signatures.` Do NOT show per-member or k-of-n progress for this leg. Do NOT invent counts.

**Anchor detail (D-18, D-33)**
- Section title: `Anchor`
- Sub-steps (reuse `AnchorSubSteps`): `Signed` -> `Broadcast` (txid `Mono` plus `View on explorer` accent link) -> `Confirmed`. "Anchored" narration only at confirmed.
- Hermetic (no-broadcast) service: `This no-broadcast service does not publish to Bitcoin, so there is no on-chain anchor to show.`
- Fallback (D-33): `This cohort anchored via the k-of-n fallback path with {k} of {n} signatures.` Per-member inclusion marked where derivable.

**Funding stage (D-36 through D-42, live + broadcast only)**
- Section title: `Funding`
- Beacon address: `CopyField` label `fund this cohort's beacon address ({activeNetwork})`, value `bitcoin:{address}`, plus a `View on explorer` accent link.
- Suggested minimum (D-37, one consistent number): `Send at least {n} sats to this address.`
- Waiting state: `Waiting for funds. Send at least {n} sats from your own wallet, then this stage advances automatically.`
- Seen-in-mempool state: `Funding seen in the mempool. Waiting for it to confirm.`
- Funded state: `Funded and confirmed. This cohort can anchor on-chain.`
- Dead-end state (D-37): `Funded below the minimum. Topping up cannot fix this, so re-create the cohort on a fresh address.`
- Window-closed state (D-38, clean lapse): `The funding window closed before funds arrived.`
- Truncated-window disclosure (D-38): `This cohort's remaining lifetime shortens the funding window to about {n} min.`
- Blind-lapse / observation-gap (D-39): `The funding window ended while this service could not observe the chain. Check the address before reusing it.`
- Esplora-unreachable mid-flight (D-43): `This service can't observe the chain right now, so the funding state below may be stale.`
- Recovery-key disclosure (D-40, always shown on the funding stage):
  - operator-held: `Operator-held recovery key: if this cohort fails below the fallback threshold, you can recover funds sent to this address.`
  - throwaway: `Throwaway recovery key: if this cohort fails below the fallback threshold, funds sent to this address are unrecoverable.`
- Mainnet real-money line (D-42): `Bitcoin mainnet: this address receives real funds. Change returns to the beacon address and is timelocked unless LIVE_CHANGE_ADDRESS redirects it.`

**Activity log (D-21, D-22)**
- Section title: `Activity`
- Empty: `No activity yet.`
- Entries: server wall-clock time plus event text; tone by level (info muted, good, warn, bad). Rejects, nonce progress, and non-fatal errors all appear (D-22).

**Export (D-34)**
- Section title: `Export`
- Button (ghost): `Download monitoring record (JSON)`
- Help: `Downloads exactly what this page shows, plus the activity log. Off-chain artifacts stay referenced by hash at /cas/.`

**Poll failure / session / restart (D-16, D-24, D-25)**
- Unreachable banner (bad tone, D-25): `Can't reach this service. Showing the last known state and retrying quietly.`
- Session expired mid-monitoring (D-16, honest re-login): `Your operator session ended. Sign in again to keep monitoring. Monitoring rebuilds from this service's state after you sign in.`
- Process-restart empty state (D-24): the empty-state body above already carries the in-memory-clears-on-restart line.

**Participant-side strings (D-44, D-45, D-46)** (these ship on the participant surface but are part of this phase's contract)
- Join-time live notice (D-44): `This cohort anchors on-chain. The operator funds its beacon address after seats fill, so keep this tab open.`
- Awaiting-funding wait copy (D-44): `Waiting for the operator to fund this cohort's beacon address.`
- Stall copy fix (D-45): positive stall (submitted, never validation-requested): `This service stalled while collecting updates.` Uncertainty-honest (submitted, validation-requested, still unsigned): `Co-signing could not complete, and this service didn't say why.`
- Unconfirmed-signal resolve outcome (D-46): `A beacon signal is awaiting confirmation. Resolve again after it confirms.`

## UI Considerations

> Shape-rooted UI state coverage for the Phase 4 surfaces (empty / loading / error / populated / partial / overflow / zero-one-many / long-text). Empty-state and error-state COPY live in `## Copywriting Contract` above; this table covers state coverage and references those rows.

Applicable state considerations resolved: 9 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | cohort list | ✅ covered | Zero cohorts renders the `No cohorts yet` heading + in-memory-clears body (Copywriting Contract, D-24). |
| empty | members / submissions / activity log | ✅ covered | Each concern section renders its documented empty line (`No one has joined yet`, `not yet submitted`, `No activity yet`). |
| loading | first poll before data lands | ✅ covered | Health strip freshness dot starts neutral/checking; sections render their empty line until the first read lands (no spinner invention, mirrors participant `checking` window). |
| error | unreachable service | ✅ covered | Consecutive poll failures raise the bad-tone `Can't reach this service` banner; displayed state freezes honestly, quiet auto-retry (D-25). |
| error | session expired mid-monitoring | ✅ covered | 401 discrimination triggers the honest re-login copy and redirect to the login panel (D-16); network/5xx does NOT redirect, it freezes. |
| populated | drill-down with members/submissions/anchor | ✅ covered | Full concern sections plus stage timeline; per-member round-state chips answer "who is holding this cohort up" (D-31). |
| partial | some members submitted, some not; co-sign mid-round | ✅ covered | Submissions list splits submitted vs not-yet; co-sign shows `{k} of {n} nonces received`; partial-sig leg shows the honest awaiting line with NO invented count (D-32). |
| zero-one-many | 0 / 1 / many cohorts across the four list groups | ✅ covered | Groups (`Needs attention`, `Active`, `Drafts`, `Ended`) render only when non-empty; ended group bounded at the 24-cap (D-23). |
| overflow | long DID / pubkey / txid / beacon address | ✅ covered | Shortened display plus `CopyField` copy-full and `Mono` truncation; raw JSON and pubkeys sit in a scroll-capped `Expander` (`max-h-80 overflow-auto`), never grow the card. |
| overflow | activity log ring buffer, many entries | 🧪 backstop | `LogPanel` scrolls internally at a fixed height and auto-follows; the server ring is bounded (D-21). Held-out visual-state check: a full ring renders without page growth. |
| long-text | funding disclosure stacking (mainnet + throwaway key + truncated window + observation gap simultaneously) | 🧪 backstop | Multiple funding disclosure lines can co-occur; they stack as separate short paragraphs inside the funding `Card`. Held-out visual check: worst-case stack stays readable and does not overflow. |
| overflow | many concurrent cohorts in the summary list on one screen | ⚠ unresolved | No virtualization planned (single-box, in-memory, modest cohort counts). Planner treats "large cohort counts render acceptably without virtualization" as an assumption; revisit if it bites. |
